## 재현한 버그: 추가 화면으로 전환해도 기존 화면이 남는다

`src/webview/main.ts`의 `showEditor()`는 기존 화면에 `hidden = true`를 설정한다. 그러나 `media/main.css`의 `.screen { display: flex; }`가 브라우저 기본 `[hidden]` 스타일보다 우선한다. 따라서 기존 화면과 추가 화면이 모두 표시된다.

번들 UI에서 ＋ 클릭 후 확인한 결과:

```json
{
  "screens": [
    { "hidden": true, "display": "flex", "height": 780 },
    { "hidden": false, "display": "flex", "height": 780 }
  ],
  "bodyHeight": 1560
}
```

현재 화면 아래까지 스크롤해야 추가 UI가 보인다. 초기 화면에서도 숨긴 빈 편집 화면 때문에 전체 문서 높이가 늘어난다. 이미지의 화면 전환 방식과 다르며, 우선 수정할 버그다. 검토 과정에서는 수정하지 않았다.

## 이미지·요청과 다른 구성

| 항목 | 이미지 및 사용자 의도 | 현재 초안 | 판단 |
| --- | --- | --- | --- |
| ＋의 진입 흐름 | 기존 항목/에이전트 선택 또는 새 CLI 추가 | ＋ 클릭 시 작업 이름, 저장된 프로필, 템플릿, 사용자 정의 버튼이 한 화면에 함께 배치됨 | 선택 흐름이 분리되어 있지 않음. 화면 숨김 버그도 동반 |
| 주 화면 구성 | 간결한 선택 목록, 행별 설정/리로드, 선택한 에이전트 화면 | 작업 목록, 이름·ID 편집, 다수 관리 버튼, 터미널을 한 화면에 함께 배치 | 관리 기능이 터미널 화면을 많이 차지함 |
| 행별 관리 | 이미지에는 행별 톱니바퀴·리로드와 드래그 핸들 | 세션 행은 선택 버튼이며 관리는 선택 후 별도 영역에 나열 | 이미지의 행별 관리 방식과 다름. 목록 정렬 드래그 없음 |
| 기본 에이전트 | AgentMux 예시에는 Claude, Codex, OpenCode, Antigravity, Devin | 현재 AI 템플릿은 Claude, Codex, OpenCode. PowerShell과 CMD도 제공 | 예시의 모든 기본 제품을 포함하지 않음. 필수 템플릿 범위 확인 필요 |
| 표시 위치 설정 | 확장 설정 GUI에서도 Primary/Secondary Sidebar/편집기 탭 선택 | `package.json`에 설정 항목이 없고, 화면의 ‘위치’ 메뉴에 편집기 열기/사이드바 이동 버튼만 있음 | 설정 GUI와 Primary/Secondary 명시 선택이 빠짐 |
| VS Code 드래그 이동 | 위치를 드래그로 자유롭게 변경 | 사이드바 뷰와 편집기 패널을 각각 등록. 교차 드래그는 미검증 | 사이드바 ↔ 편집기 교차 드래그 요구는 완료되지 않음 |
| 모바일 크기·입력 | 큰 선택 행과 버튼, 여러 줄 입력창 | 기본 글자 13px, 버튼 최소 32px, 입력창은 단일 행 `input` | 휴대전화 가독성·터치 영역과 여러 줄 입력 방식이 다름 |
| 제품 화면의 설명 | 에이전트 선택과 작업이 중심 | 위치 메뉴 등에 API/드래그 미검증 설명과 백엔드 종료가 노출됨 | 개발 설명을 제품 화면에서 줄일 필요가 있음 |

이미지 첫 장의 handide 상단 바와 에이전트 선택기는 handide가 제공하는 외부 UI다. 독립 확장에서 그 바 자체를 다시 만들거나 handide에 기능을 내장하는 것은 별개의 변경이다. 어떤 UI를 확장이 소유하는지 구분해서 최종 배치를 정해야 한다.

## 터미널 설치 요구의 반영 상태

현재 초안은 `@xterm/xterm`과 `node-pty`를 사용하며 tmux를 필수 실행 경로로 쓰지 않는다. Windows용 CLI 설치 안내도 별도로 정의되어 있다. 따라서 제공 이미지와 같은 `brew install tmux` 안내를 그대로 재현하는 구조는 아니다.

다만 개발 폴더의 의존성 설치와 실제 VSIX 배포는 다르다. 다른 Windows PC에서 개발 도구 설치 없이 터미널이 시작되는지는 이번 검토에서 확인하지 않았다. 외부 CLI 자체의 설치·로그인까지 완료된 것으로 판단하지 않는다.

## 문서 상태의 차이

README 상단은 ‘Windows용 초안 구현’으로 변경되어 있지만, 뒤쪽 ‘구현 방향 제안’에는 아직 아무것도 구현하지 않았다는 설명이 남아 있다. 마지막 문장에도 요구사항 문서만 작성했다고 되어 있다. 현재 소스가 존재하므로 이 상태 설명은 서로 맞지 않는다. 기존 구현 작업과 충돌하지 않도록 이번 검토에서는 README를 수정하지 않았다.

## 우선순위 제안

1. 숨김 화면이 함께 표시되는 버그 수정.
2. ＋ 이후 기존 항목 선택/새 CLI 추가 흐름을 구분.
3. 관리 입력과 버튼을 별도 편집 화면 또는 행별 메뉴로 정리.
4. 모바일 버튼 크기·여러 줄 입력과 화면 비율 조정.
5. 위치 설정과 드래그 전환 검증, VSIX 설치 환경 검증.

이 문서는 확인 결과다. 코드 수정이나 요구사항 변경을 완료했다는 의미는 아니다.
