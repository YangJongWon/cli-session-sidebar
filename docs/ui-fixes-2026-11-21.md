# GUI 수정과 검증

수정일: 2026-11-21

## 수정 내용

- `[hidden]`을 명시적으로 적용해 추가·편집 화면을 열 때 기존 화면이 함께 표시되는 버그를 수정했다.
- ＋ 진입 화면에 에이전트 드로워를 기본 펼침 상태로 표시한다. ‘에이전트 선택’을 한 번 더 누르는 중간 화면을 없앴고, 접힌 상태에서도 ‘새 CLI 추가’는 바로 사용할 수 있다. 저장된 프로필에는 시작과 편집을 각각 제공한다.
- 확장의 최초 화면에서도 에이전트 목록을 즉시 펼친다. ‘에이전트 선택 / 새 CLI 추가’ 두 버튼을 보여주던 시작 화면을 삭제했다. 최초 화면의 등록 버튼은 CLI 등록 폼을 직접 열고, 기존 작업이 선택된 상태의 ＋는 새 작업 목록을 연다.
- 맨 위를 작업 탭 / + / … 구성으로 바꿨다. 작업 탭에서 바로 전환하고 +는 새 작업 탭을 연다. CLI 등록은 에이전트 목록 바로 위에 배치한다. 탭바는 등록·편집 중에도 유지하고, 부가 관리는 … 메뉴에서 제공한다.
- 목록 이름을 ‘커맨드’로 바꾸고 등록한 CLI와 기본 커맨드를 함께 표시한다. +는 마지막 작업 탭 바로 옆에 붙이고 …는 맨 오른쪽에 둔다. 환경 설정은 커맨드 제목 오른쪽에서 제공한다. Chromium·WebKit에서 실제 배치, 등록한 일반 CLI의 편집, 이름 변경 반영, 삭제와 관리 목록 갱신을 확인했다.
- 선택 목록은 CLI별 표식·이름·실행 프로그램을 함께 표시하는 행으로 정리했다. ‘내 CLI’와 기본 CLI를 구분하고 등록은 상단에서 시작한다.
- 등록 화면은 기본 입력, 실행 설정, 접을 수 있는 고급 설정으로 나누었다. 파일·폴더 선택은 입력란에 붙여 배치하고, 저장과 저장 후 시작은 하단에 모았다. 좁은 화면과 밝은·어두운 테마 캡처도 확인했다.
- 기본 AI 템플릿에 Antigravity와 Devin을 추가하고, 사용자 지정 CLI 등록을 유지했다. Antigravity의 재개 명령은 설치된 CLI에 맞춰 직접 지정한다.
- 주 화면을 선택한 터미널 중심으로 정리했다. 상단 작업 이름으로 별도 목록을 열고, 각 행에서 설정·재연결을 선택한다.
- 이름·재개 ID·프로필 편집과 중지·삭제를 별도 관리 화면으로 옮겼다. 확인 창은 확장 화면 안에서 제공하며 취소하면 프로세스에 명령을 보내지 않는다.
- 목록의 포인터 드래그 및 키보드 ↑ ↓ 순서 변경을 저장한다. 다른 창에서 추가된 작업이 오래된 목록의 저장 때문에 사라지지 않도록 보존한다.
- Primary Sidebar, Secondary Sidebar, 편집기 탭을 ⋯ 메뉴와 확장 설정에서 선택한다. 위치 설정은 변경 시에 적용하고, 같은 설정을 재실행 때 반복 적용해 사용자의 드래그 배치를 되돌리지 않는다.
- 위치를 명시적으로 선택할 때 확장 자체의 대상 컨테이너만 기본 위치로 돌린 후 해당 뷰를 옮긴다. 전체 VS Code 레이아웃은 초기화하지 않는다.
- VS Code 1.106 이상에서 지원하는 Secondary Sidebar 컨테이너를 사용한다. 호환되지 않는 이동 명령은 성공으로 표시하지 않고 오류를 안내한다.
- 여러 줄 입력창, Enter 줄바꿈, 보내기/Ctrl·Cmd+Enter 전송을 제공한다. 여러 줄 전송에는 bracketed paste를 사용하며, IME 조합 완료 Enter가 명령을 전송하지 않도록 했다.
- 터치 환경에서 버튼 높이를 최소 44px로 늘리고, 작아진 화면에서도 입력창이 보이도록 배치했다.
- 프로필 저장 응답의 ID를 유지해 연속 저장이 기존 항목을 수정하도록 했다. 이전 편집 화면의 늦은 저장 응답이 새 편집 화면의 ID를 덮어쓰지 않도록 폼 식별자를 사용한다.
- CLI 시작이 실제로 성공한 이후에만 ‘작업을 시작했습니다’를 표시한다. 실행 실패는 실패로 보고한다.
- 제품 화면에서 드래그 API 설명과 백엔드 내부 상태 설명을 제거했다. 백엔드 종료는 VS Code 명령 팔레트에서 제공한다.

## 검증

### 타입 및 저장·명령 검사

- `npm run check`: 통과.
- `npm test`: 명령 조립, 저장과 실행 구분, 순서 변경의 디스크 보존, 재생성 후 복원, 다른 창의 추가 작업 보존, 중복 순서 거부, CLI 시작 실패 시 성공 응답 금지 검사 통과.

### 브라우저 UI

`npm run check:ui`의 실제 번들 UI를 Chromium과 WebKit에서 실행했다.

- 440 × 780 휴대전화 크기, 터치 환경에서 추가·편집 화면 한 개만 표시.
- 별도 추가 선택, 기본 에이전트 목록, 사용자 정의 CLI 저장·재저장.
- 행별 설정·재연결 및 포인터·키보드 순서 변경.
- 중지 확인의 취소·확인 동작.
- 한글·여러 줄 전송 및 IME Enter 중복 전송 방지.
- 위치 메뉴의 명령 전달.
- 360 × 400으로 축소했을 때 입력창 유지.
- 브라우저 JavaScript 오류 없음.

이 검사는 호스트 메시지를 대체한 UI 회귀 검사다. 실제 CLI 프로세스와 VS Code 위치 이동은 아래 별도 검사에서 확인했다.

### Windows 터미널

`node dist/smoke.js`: 실제 PowerShell 출력, 연결을 끊은 뒤 같은 실행 프로세스에 재연결, 중지·백엔드 종료 검사 통과.

### 실제 VS Code

격리된 handide/serve-web 서버의 VS Code 1.145.2에서 확장을 로드해 확인했다. 기존 운영 서버를 재시작하지 않았다. 테스트 서버는 데스크톱 확장 자동 가져오기를 끄고 이 확장과 테스트 브리지만 사용했다.

- Primary Sidebar에서 실제 Webview 렌더링.
- Secondary Sidebar로 실제 이동, ＋ 화면의 단독 표시.
- 편집기 탭으로 열기.
- Primary Sidebar로 복귀.
- Secondary 배치가 브라우저 새로고침 후에도 유지.

최종 빌드 결과: `check-output/vscode-cc8ujg/result.json`, 화면: `check-output/vscode-cc8ujg/secondary.png`. 검사 후 격리 서버와 분리 실행된 테스트 프로세스 정리까지 완료했고 검사 스크립트가 종료 코드 0으로 끝났다.

## 남은 제약

- 사이드바 ↔ 편집기 탭 사이의 직접 드래그는 구현하지 않았다. 현재는 ⋯ 메뉴 또는 확장 설정으로 전환한다. 사이드바 사이 및 편집기 탭 사이에는 VS Code 기본 이동을 사용한다.
- 실제 iPhone Safari와 실제 소프트 키보드 검증은 수행하지 않았다. WebKit 에뮬레이션을 실제 기기 검증으로 표시하지 않는다.
- 다른 Windows PC에 VSIX만 설치하는 배포 검증, 임의의 외부 CLI 설치·로그인, CLI별 과거 대화 자동 탐색은 이번 변경의 검증 범위에 포함하지 않는다.
